# Integration

Each must-have from `ganger/brain/CONSTITUTION.md`, with the file and function that implements it. Every screen reads and writes the Dexie database in `src/db/schema.ts` (through `src/lib/store.ts` or the table itself); no screen keeps its own copy of stored data. Every screen is reached from the sidebar in `src/App.tsx`, which is only shown once a workspace has been chosen on the first screen. The same list, in machine-readable form, is `ganger/reports/coverage.json`.

## How the pieces connect
- **Workspaces (pen names):** the first screen (`WorkspaceGate`) offers "New Workspace" and the workspaces already saved on this computer. "New Workspace" opens the create menu: type a pen name, or "Generate a pen name", which makes a workspace with no name yet and opens Manuscripts on the pen name generator. Every section (Manuscripts, Roadmap, Outline, Write, Edit, Format, Book Cover, Export, Translate, Settings) is nested inside the workspace. The "Workspaces" button at the bottom of the left menu (`WorkspaceSwitcher`, above Settings) switches workspace or adds one. The left menu collapses to icons: the chevron at the top of the menu (`src/App.tsx`, with `SIDEBAR_KEY` remembering the choice) hides the labels and keeps the icons, and `Brand` shows the book mark alone.
- **Pen names and mockups:** in the new-manuscript menu the pen name generator depends on the genre chosen there (`nameStyleFor` in `src/lib/penNames.ts` picks the style of names). It gives a brief list, each shown on a cover mockup in the genre's look, and the author can type a name instead, which also gets a mockup. Choosing a name sets the workspace's pen name. The same picker is on the Book Cover screen. The "Generate pen names" button stays grey until a genre is chosen. When the author has an image AI key, each generated name is drawn as a cover mockup by that model (`PenNamePicker` calls `generateCoverImage` in `src/lib/imageAi.ts`, one picture at a time, with a "Draw cover" button for any one that failed); without a key the drawn mockup from `CoverMockup` is shown. Every cover mockup or picture opens full size when clicked (`ZoomView` and `CoverImage` in `src/components/CoverMockup.tsx`).
- **Manuscripts:** there is no manuscript drop-down in the menu. `src/screens/Manuscripts.tsx` lists the workspace's books on the left, with series grouped under their name (Book 1, Book 2 ...); choosing one opens its options on the right. "New manuscript" (with its type, the genre guide and the pen name) and "Import manuscript" (`planImport` and `importManuscript` in `src/lib/importManuscript.ts`, reading .txt, .md, .html, .docx or .epub) both open the new manuscript on the Roadmap.
- **Types and series:** `ManuscriptType` is short story, novella, novel or series (`manuscripts.type`; a book made before types is a novel). A series is a container row (type `series`, holds no text) and each of its books is a manuscript with `seriesId` and `volumeNumber`. The Outline screen shows the series' books as a choice, and the Write, Edit, Format, Book Cover and Export screens work on whichever book is chosen, as they do for any book.
- **Roadmap:** `src/screens/Roadmap.tsx` shows a Kanban board of cards from outline to publish (`src/lib/roadmap.ts`, `roadmapCards`). Each card can open the screen it belongs to.
- **Genre guide:** "New manuscript" asks for a title and a genre (Fiction or Non-fiction, then a genre with its guide). The form is laid out as Title beside Type, the Genre dropdown under Title, and the Fiction / Non-fiction buttons under Type (`GenrePicker` returns those cells for the form's grid). The genre sets the target word count and keywords, and can start the outline with its structure (`applyGenreStructure`). The AI staff are told the genre through `genreContext`.
- **Book Cover:** the author's image key is separate from the text AI key. `BookCover` builds the prompt from the brief, asks the image model for 1 to 3 pictures, stores each in `coverConcepts`, and "Use as cover" puts one on the manuscript so Export includes it.
- **Story info (Outline):** the "Story info" button in the Outline header opens a panel on the right (`StoryInfoPanel`, `src/components/StoryInfoPanel.tsx`) with three lists: characters, locations and situations. Entries are saved per book with `createStoryEntry`, `patchStoryEntry` and `deleteStoryEntry` in `src/lib/storyInfo.ts`, in the `storyEntries` table (schema version 6). The Outliner panel and the Story info panel share the right-hand side, so only one is open at a time. The outliner AI is given the story info as text (`storyInfoToText`). A book's story info is deleted with the book (`deleteManuscript`) and is included in backups.
- **Scenes:** each chapter is a stack of scenes stored inside the chapter HTML as `<section data-segment>` blocks, so revisions, suggestions, the preview, the epub and the Word draft all use the one stored text.
- **Editing workflow:** progress (`editWorkflow`) is stored on the manuscript; each pass can use a different model, chosen in the Edit screen and stored per provider in `settings` (`editModels`).
- **Outline to Write:** "Start writing this" (`chapterForOutlineItem`) and "Create chapters from outline" (`chaptersFromOutline`, in outline order) make `chapters` rows and link them to the outline item through `chapterId`.
- **Format to Export:** The Format screen stores `FormatSettings` on the manuscript. The live preview and the epub both use `buildCss` and the same chapter markup, so the preview matches the exported file. An empty scene break ("None") writes no mark between scenes.
- **Export:** `buildEpub` produces an EPUB 3 file (table of contents, cover, title page, copyright page, KDP metadata) that the author uploads to Amazon KDP. `buildDraftDocx` produces a double-spaced Word file with a title page, a page per chapter, scene breaks and page numbers, for a human editor.
- **Ghostwriter:** the "Ghostwriter" button in the Write header opens a menu on the right (`Ghostwriter`). It is an `AgentChat` with the `ghostwriter` role (`src/lib/ai.ts`), saved in `agentMessages`, and is given the genre, the chapter so far, the selected scene and the research items marked "The Ghostwriter can use this" (`researchContext`). "Add to scene" on any reply writes it into the selected scene.
- **AI staff and keys:** `src/lib/ai.ts` (`askAi`, `requestStageReview`, `requestFormatPreset`) calls the provider the author picks in `src/screens/Settings.tsx`: OpenAI, Anthropic, Hugging Face (its OpenAI-compatible router) or Ollama on this computer (`src/lib/providers.ts`). Keys are encrypted by `src/lib/keyVault.ts` (AES-GCM under a non-extractable key kept on this computer). Settings lists them with "Use this key", "Revoke" and "Delete". Ollama needs no key, only a server address.
- **Word lookup:** `src/lib/lookup.ts` uses the free dictionaryapi.dev for definitions and Datamuse for synonyms, antonyms and spelling suggestions. It needs a connection; the card says so when there is none. Nothing is sent until the author clicks "Look up".
- **Backup:** `createBackup` reads every table except the encrypted key list and writes one JSON file (covers as base64). `restoreBackup` replaces the data in one transaction, after `BackupControls` has shown what the file holds and what would be replaced.

- **Translation:** a translation is a second book in the same workspace, linked to the original. Its chapters are laid out as empty pieces to be filled. Asking for a chapter translates just that chapter; the author reads it beside the original, may ask the AI proofreader for suggestions (in Edit they are accepted or rejected like any other), and approves it. Deleting a book deletes its translations (`deleteManuscript` in `src/db/schema.ts`).
- **Narration:** the "Listen" button in Write reads the open chapter aloud. "This computer's voice" uses the browser's speech and works offline. "AI voice" uses the OpenAI speech model on the author's key. The audiobook in Export uses the same AI voice, one MP3 per chapter.

## Accounts and connection
- No sign-in: nothing in the app asks for an account.
- Offline: all data is local (IndexedDB), and `public/sw.js` lets the built app open with no connection. The AI staff, the Book Cover pictures and the word lookup need a connection (Ollama runs on this computer and does not); their panels turn back on by themselves when the connection returns (`useOnline` in `src/lib/hooks.ts`).

## Settings
The app reads nothing from the environment (`.env.example` says so). The author's AI key and image AI key are entered in the app under Settings and kept encrypted.
